One Vocab, Four Languages

A single 10,000-token byte-level BPE vocabulary, trained jointly on the Wikipedia "India" article in English, Hindi, Telugu, and Marathi — then scored on how evenly it compresses each one.

One shared vocabulary, but every token is only actually used by the languages whose text it shows up in when encoded — each column below is the set of tokens that language's own article actually uses.

Assignment: pick a single 10,000-token vocabulary, train it jointly across all four languages, then measure X = (word count) / (token count) for each language's article. The self-score is 1,000 / (largest X − smallest X) — a tokenizer that compresses all four languages about equally evenly scores higher than one that's great at one language and poor at the rest.

Why a joint vocab matters: merges are a shared, scarce resource. Hindi, Telugu, and Marathi are encoded as multi-byte UTF-8, so some of their merge budget goes toward gluing 2–3 raw bytes back into a single character before word-level compression can even begin. A pure global frequency race would let whichever language's byte pairs simply occur most often (not necessarily English) crowd out the others' merges early — so instead, every merge is spent on whichever language currently has the lowest live fertility (words / tokens so far), continuously chasing down the worst performer instead of splitting the budget on a fixed schedule. A language stops competing once it genuinely runs out of repeated pairs to merge, freeing the rest of the budget for the others.

Marathi was picked as the fourth language deliberately: it's Indo-Aryan and Devanagari-script like Hindi, so it lands in a similar fertility range instead of becoming a new extreme and widening the spread.
