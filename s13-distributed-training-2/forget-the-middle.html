Forget the Middle

Session 12 divided what a training run stores. This one divides what it computes — and then removes most of it instead. A reversible stack keeps the state entering the layers and the state leaving them, throws away everything in between, and rebuilds it on the way back. Activation memory stops depending on depth.

01Why this session exists at all computed

ZeRO spreads the optimizer state, then the gradients, then the weights across the copies of a model. Every GPU still runs the whole model on its own micro-batch, first layer to last. Three things break under that arrangement, and each is a section of this session.

ZeRO never divides activations. One sequence of 8,192 tokens through the 30B model stores 127.5 GiB of intermediate results. An H100 holds 74.5 GiB. Take ZeRO-3 to its limit, put the entire training state at 16/N, and that one sequence still does not fit.

ZeRO-3 needs a whole layer to fit, and rebuilds it every step at a cost of 3 parameter-sizes of traffic. And one long sequence cannot be split by data parallelism at all — a 131,072-token sequence produces 2,040 GiB of activations and is a single sample.

Session 12 answered our model's state does not fit. This one answers our model's computation does not fit. Tensor, sequence, pipeline and context parallelism divide the computation, and therefore the activations. Reversibility does something else entirely: it stops storing them.

02The model, and the two numbers that matter computed

One model is used for every calculation in this session: 30.2 billion parameters in 96 layers, hidden size 5,120, 40 attention heads sharing 8 sets of keys and values. Training one weight costs 16 bytes — the weight, its gradient, a 32-bit master copy, and the optimizer's two running averages.

Activations are counted at about 34 bytes per token per unit of hidden size, with FlashAttention, from Korthikanti and colleagues' 2022 census of every tensor a transformer layer keeps. That is 1.33 GiB per layer for an 8,192-token sequence, and 127.5 GiB across 96 layers.

The pipeline bubble

A pipeline stage waits while the first micro-batch travels to it, and again at the end of the step. With p stages and m micro-batches, the share of the step spent waiting is (p−1)/(m+p−1). More micro-batches shrink it.

Zero-bubble schedules split the backward pass into the gradient for the input and the gradient for the weights; the weight part can wait, so it fills idle slots. Sea AI's ZB-H1 cuts the bubble to a third of 1F1B's at the same peak memory.

05Where each form is allowed to live reference

A cluster has fast wiring inside each node and slower cable between them, so the forms nest from the most demanding outward: tensor innermost, then context, then pipeline, then data parallelism on the outside.

Tensor parallelism at degree 8 fills one node over NVLink. Data parallelism spans the nodes over InfiniBand. Most clusters are rail-optimized — card k of every node reaches the same switch — so pipeline and data-parallel partners sit at the same position in different nodes and their traffic stays on one rail.

Production layouts combine all of it. Llama 3 405B ran on up to 16,384 H100s with tensor, context, pipeline and data parallelism together. DeepSeek-V3 is the instructive counter-example: it trained with no tensor parallelism at all, because its H800s had NVLink at only ~3.2× InfiniBand rather than 9×, and that ratio is what makes tensor parallelism affordable.

06Reversibility: the rule computed

Every section above divides the activations across more GPUs. A reversible network removes most of them instead.

An ordinary block adds its output to its own input. That cannot be run backwards: recovering the input would need f evaluated at the input being recovered.

ordinary, not invertible
p[l]   = p[l-1] + f(p[l-1])

midpoint — reaches two layers back, evaluates in between
p[l+1] = p[l-1] + 2h · f(p[l])
p[l-1] = p[l+1] − 2h · f(p[l])   ← p[l] is already in hand

The backward pass walks down the stack, and at every step reconstructs the input it needs from the output it already holds. Nothing in between has to be kept. This is not recomputation: recomputation stores the input of every group of layers and runs them forward again. A reversible stack stores no layer inputs at all.

Two constraints come with it

The forward pass must be deterministic. The backward pass rebuilds activations by computing the same block again, and a random dropout mask would make the reconstruction differ from what the forward actually used. Dropout of zero is a correctness requirement here, not a tuning choice — and it is gated in section 12.

The rule is only marginally stable. The step size and blend coefficient have to sit in a narrow range, and section 10 measures what happens outside it.

07Is the implementation correct? measured

This is the section everything else depends on, and it is the reason the loss curve is not evidence. A reversible stack that reconstructs slightly wrong still trains. The loss still falls. It simply trains a different model than the one you wrote down.

So reversible gradients are compared against ordinary autograd, and the comparison is run twice at different precisions, because those answer different questions. Is the arithmetic exact? Ask in float64 — an exact implementation differs only by rounding, so the error must collapse when precision rises. How much does it drift? Ask in float32.

Euler is in the comparison because it fails

The assignment asks which variant worked — "mid-point, euler, etc". Plain forward Euler, p + h·f(p), has exactly the same flaw as the ordinary residual: inverting it needs f at the state being recovered. It is not reversible, and saying so with a measurement is worth more than leaving it unmentioned.

08The three runs measured

Same tokens, same seed, same schedule. Run 1 against run 2 isolates what reversibility costs, because only the memory path changes. Run 2 against run 3 isolates what it buys, because the saved memory is spent on batch size.

Where this disagrees with the paper

The method's authors report a batch ratio of 9.9× (26 → 257 on an 80 GB H100, and "about 10" on five different cards) and a throughput gain of 2.01× (56.96 → 114.49 samples/s), at an estimated overhead of 30–50%. This run got 5.0×, 1.007× and 16%. All three differences have the same two causes, and neither is a disagreement about the method.

10Reconstruction drift measured

Not in the session notes, and it is what limits how deep a reversible stack can go. Reversal subtracts, so each rebuilt state carries the error of the one above it and the error compounds down the stack. In low precision it compounds much faster — the same failure mode Session 12 measured when a bfloat16 ring summed 1…32 to 524 instead of 528.

11The blend coefficient, and a constraint on what it can mean measured

The session records Lightning LM running a step size of 0.25 and a blend coefficient of 0.5, and says these must be set explicitly because library defaults differ. It never gives the formula. Under the natural reading, the inverse divides by (1−γ) — so it multiplies any reconstruction error by 1/(1−γ) once per layer.

p[l+1] = (1−γ)·p[l-1] + γ·p[l] + 2h·f(p[l])
p[l-1] = ( p[l+1] − γ·p[l] − 2h·f(p[l]) ) / (1−γ)   ← amplifies, every layer

13What reversibility changes upstream computed

Reversibility does not make memory free. It moves the constraint. Activations stop being the term that decides the layout, and the weights and optimizer state become that term instead — which are the things ZeRO divides, so Session 12's decisions move back up the order.

Applied to one node of eight B200s at TP = 8, the state per GPU is 56.25 GiB either way. Stored activations stop that node at 32,768 tokens; rebuilt ones let the same node hold 131,072 tokens with 108 GiB still free.

form of parallelismwhat reversibility does to it
Tensorunchanged — it divides the weight matrices, and the weights are still there
Sequencenow divides the boundary states, which are small; its original job is gone
Pipelineloses one of its two reasons — it divided state and activations by layer
Contextneeded only at much longer sequences; the threshold moves out ~100×
ZeRO stagesmore important — they divide what now fills the card

One interaction needs care. Under ZeRO-3 a GPU holds only a slice of each layer's weights and gathers them once in the backward pass. A reversible backward reads those weights a second time, when it rebuilds the activations, so the gather has to happen there too. The Lightning LM report puts it directly: the recompute path is a second forward pass, and every parameter the forward gathers has to be gathered again for it.

What is not here

Stated rather than buried. The parallelism sections are arithmetic — sections 01 to 05 and 13 are about a 30B model on many GPUs, and this ran on one T4. fp16 reversibility is measured but not used: the training runs use autocast, keeping the residual stream in fp32, because section 10 shows what happens otherwise. Only midpoint was trained — revnet and blended are verified correct and measured for drift, but the three required runs all use the rule the session specifies.
